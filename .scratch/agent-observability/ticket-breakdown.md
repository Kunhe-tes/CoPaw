## 新增前置任务

### 01：设计完整埋点契约并实现独立观测内核

**What to build:** 后续业务埋点有一套统一、可验证的独立观测接口；使用代表性执行场景即可生成符合入库契约的安全JSON日志，无须各功能票重复设计身份、Span语义、生命周期或输出类。此票是用户要求的公共内核前置项，不包含全业务挂点、数据库投影器或页面开发。

**Blocked by:** None (can start immediately).

**拟定核心职责（类名可随项目风格调整，不要求一职责一文件）：**

- 类型化事件/上下文/范围模型：统一Run、Attempt、Span、事件槽、业务引用、受控指标、关系及证据字段。
- 独立上下文管理：准入开关快照、绑定/恢复、异步任务隔离及审批/SubAgent的元数据序列化载体。
- 观测门面与Span生命周期：显式开始/结束、单调计时、独立技术/业务状态、增量事件；关闭时低成本，不改变业务异常/取消语义。
- 安全事件输出：白名单投影、UTF-8字节预算、专用有界队列/stdout输出、丢弃计数和有界关闭。

**验收标准：**

- [ ] 先形成覆盖主请求、Agent连续执行、模型逻辑调用/可见请求尝试、真实Tool、审批、SubAgent、资产与正文引用的埋点矩阵；每项明确真实边界、拥有者、身份/父关系、必填字段、去重槽、结束责任和缺失降级，不用旧SDK回调作为事实来源。
- [ ] 提交核心类职责、最小公开接口和调用时序设计，明确数据模型/上下文/门面/输出依赖方向；不额外建设通用插件框架或复制业务执行器。
- [ ] 统一实现代表性场景需要的核心接口，业务观察点由后续票接入，不在本票一次性铺开全部挂点。
- [ ] 基于代表性Run→Attempt→Span场景验证开始/结束、失败、取消、增量事件及自包含结束摘要；生成日志可通过同一事件schema验证。
- [ ] Run/Attempt身份与根终态规则、模型重试和Agent重执行区别、审批/SubAgent快照及跨进程槽所有权均有契约测试；不在本票改变原业务状态机。
- [ ] 默认全局关闭；快照可继承，嵌套/并发上下文不串写；观测不可用、队满和序列化失败不改变被观测业务返回/异常/取消。
- [ ] 单条24KiB、可选数组/深度、4096条及8MiB队列、最多1秒关闭等设计预算可验证；不处理逐token正文，不输出敏感正文或异常原文。
- [ ] 新旧开关任意组合相互独立；新内核不连接数据库，不新增采集器或旧可观测导入依赖。
