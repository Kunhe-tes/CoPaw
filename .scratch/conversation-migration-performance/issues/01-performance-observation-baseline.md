# 01: 补齐迁移性能观测与可复现基线

**What to build:** 运维人员通过现有 prepare → migrate 入口获得可解释的阶段、数据库与正文 IO 开销，并可在相同输入和资源条件下比较优化前后结果。

**Blocked by:** None (can start immediately).

**Status:** claimed

- [ ] 区分逻辑数据库调用、实际 SQL 分块、事务开始/提交/回滚，说明各计数口径及是否重叠，不把批量门面调用误当作一次真实 SQL。
- [ ] 输出阶段墙钟耗时、处理记录数、bundle 打开及索引解析次数；并发累计 IO 时间与墙钟时间明确区分。
- [ ] 指标不含正文、凭据、敏感路径或 SQL 参数，失败及取消后仍保留可解释的进度。
- [ ] 复用现有 CLI/编排集成测试边界，提供固定输入与资源条件的本地目录、隔离 MySQL 对照运行方式，不新增迁移人工阶段。
- [ ] 基线覆盖多个小 source、单个多消息 source 和部分完成后续跑，记录数据量、预算和环境；不要求万级或真实 NAS 基线。
- [ ] 验证观测不会改变 SQL owner、source 隔离、退出语义或迁移结果，并更新指标说明。
