# 02: 消息批量写入与已提交记录批量核对

**What to build:** migrate 对消息元数据执行有界多行插入，对已提交批次按表分块读取后全量比较，使首次导入和恢复核对减少逐行往返，用户仍得到相同会话与发布结果。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 在现有 publication 事务内优先批量写入连续、同字段集合的 Message 记录，保留每行定位解析、关联及 source 归属校验。
- [ ] 使用可信表/字段白名单和参数化 prepared 多行插入，受行数、字节及服务器 packet 共同限制，不依靠忽略错误或覆盖冲突。
- [ ] 不任意重排 Session、Chat、Turn、Message 或更新记录；一条错误导致当前事务回滚，数据错误与共享数据库错误继续按既有规则分类。
- [ ] 已提交记录按表及有界 ID 集合查询，再逐条比较不可变字段；缺失、重复身份及不一致明确失败，不做抽样。
- [ ] 覆盖空、单条、满块、跨块、不同字段集合、Unicode/二进制/空值、大字段与单行 packet 超限。
- [ ] 通过现有迁移入口验证成功发布、重复执行幂等、坏 source 跳过及已发布 source 新数据保护；SQL 计数证明插入和核对由逐行变为按块。
