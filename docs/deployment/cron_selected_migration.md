# 旧页面勾选迁移到新版

## 边界

部署 Console、Scheduler 和 SWE；沿用已有数据库及服务地址配置，本次不新增表或执行 DDL。迁移没有关闭旧调度平台入口、旧接口或旧 jobs.json，切换前须自行安排旧入口停用，避免同一个会话被新旧两路同时执行。

每次勾选最多100个父任务或独立任务，父任务的全部子任务由服务端展开；不能单独勾选子任务。保留 job_id、task_chat_id、task_session_id、启停及普通/开启批调度/暂停批调度三态。迁入后默认非工作日不执行。

迁入任务的后续新版管理不回写 swe_cron_jobs；原生新版任务仍按原规则双写。新版删除迁入任务会停新定时器、逻辑删除新定义，并保留原聊天和归档资源。**旧删除接口不变，仍可能删除共享资源，请勿从旧页删除已迁入任务。**

## 页面流程

1. 旧版「定时任务」页勾选父任务/独立任务，点击「迁移到新版」。
2. 后台采集只读快照，确认框展示各组实际父子数量。此阶段没有注册或启用新平台入口。
3. 点击「确认迁移上述范围」，后台按组处理。成功组不回滚，失败组不阻止其他可迁移组。
4. 在「迁移进度」查看最近20条操作；保留 operation_id 可随时直接查询。关闭页面不取消后台执行。
5. 失败时点击「重试未完成部分」。快照采集失败会先重新采集，再次确认范围；平台注册已返回并保存的ID不会重复注册。
6. 聊天页刷新后，已迁入只使用新版，未迁入继续使用旧版。绑定冲突不合并；归属接口异常时保留已知归属并禁止误写旧接口。

运行中、已入队或等待异步结果的旧任务允许迁移，但不接管其旧执行。新版初始化为空闲，未读和已有结果按快照恢复；旧执行后续结果不会自动补同步到新版状态。

## Postman 接口

所有请求沿用现有网关 Header：X-User-Id、X-Source-Id、X-Tenant-Id、X-Agent-Id；角色按网关身份，不在Body中伪造。父任务管理者可迁其子组。

### 采集和预览

`POST /api/scheduler/cron/migrations`

```json
{"request_id":"migration-20261105-001","job_ids":["原父任务ID"]}
```

返回202及operation_id。同一次提交超时重提沿用request_id。后续请求：

- `GET /api/scheduler/cron/migrations/{operation_id}`：进度与各组数量、错误码；不返回原始任务正文。
- `POST /api/scheduler/cron/migrations/{operation_id}/confirm`：确认已采集范围或续办失败组，无Body。
- `GET /api/scheduler/cron/migrations`：当前身份最近20条记录。
- `GET /api/scheduler/cron/migrations/ownership`：可信归属，包含准备中记录和已删除任务的已完成事实；按next_cursor遍历到末页。

内部只读采集为 `POST /api/internal/cron/managed/migration-snapshot`，Body为`{"job_id":"原父任务ID"}`。Scheduler携带原请求身份Header调用；SWE在校验父任务权限后，按旧表中的关联定位子工作区，并复核文件中的真实父子关系及绑定，不初始化CronManager。

## 持久化及恢复

- swe_cron_jobs_v2：原ID定义、父子关系和Scheduler归属。
- swe_cron_job_states：原聊天/会话绑定、可恢复状态、新平台ID及管理就绪门禁。
- swe_cron_registration_journal：action=migration_batch保存冻结组快照和整体进度；action=migrate保存每个成员的可信身份、原绑定、已完成接管事实及注册进度。不得按普通临时日志清理这两类记录，否则会破坏聊天归属及迁入资源保护。
- 不复制swe_cron_executions历史。保存采集时已结束且未读的历史ID集合及水位；新版标读覆盖这部分和新版执行关联记录，不把旧在途后来完成的结果顺带标读。
- 当前实例已加载的内存状态、jobs.json和已有执行历史用于恢复；无法取得其他实例内存时返回memory_state_missing，不能宣称取得集群原子快照。
- 每组全部资源/新绑定准备完成后才启用目标入口并事务发布ready；准备中回调被业务门禁跳过。已迁入并跳过的成员不会被重新暂停。
- 后台使用有期限的数据库租约；服务重启后**不自动续跑**。过期后页面/confirm接口可人工续办，进度仍可查询。
- 平台注册响应丢失无法查询原ID，按未注册失败处理；人工重试可能留下重复的新平台记录，需要人工核对。旧平台ID只保留为快照，不作为新绑定复用。

## 预发布验收

1. 迁一个普通任务：对比迁移前后的任务/聊天/会话ID；旧定义表、旧jobs.json和旧平台入口不变；新定时器ID单独保存。
2. 迁父任务及多个子任务：确认实际数量；迁移过程中模拟一个成员注册失败，检查整组未ready、没有新业务执行；恢复后重试，已保存ID不重复注册。
3. 分别迁普通、开启批、暂停批任务，验证原启停保留。批任务只注册父入口，原提前量只作用于平台Cron，不在内部成员二次散列等待。
4. 带未读和执行结果迁入；进入原聊天只出现一个入口；已读走新版。旧在途随后完成的结果不被本次迁移标读。
5. 新接口不可用时不得回退旧写；删除新版迁入任务后不得因旧列表仍有记录而复活，原会话/归档仍保留。
6. 换用户、来源、Agent，确保列表和迁移进度迟到响应不串到新身份；无权限父任务、绑定冲突、直接选子任务均拒绝。
