# Plan Review Operate Card 改版设计

## 背景

当前聊天页中的 `PlanReviewCard` 复用了通用 `OperateCard`，但视觉语义仍偏向
“工具操作记录”。

现状存在三个直接问题：

- 头部将图标、标题、摘要、折叠箭头压缩在单行，信息层级混乱
- `summary` 被塞进标题行右侧，无法承担正文导语作用
- `Steps`、`Risks` 等英文分组直接暴露在中文界面中，观感生硬

从用户视角看，这类卡片承载的是“计划评审 / 方案确认”，更接近结构化简报，
而不是工具执行日志，因此需要调整信息架构和视觉语言。

## 目标

本次改版仅面向 `PlanReviewCard` 场景，达成以下目标：

- 第一行只展示标题，不展示图标
- `summary` 下沉到正文，作为摘要区展示
- 所有英文区块名改为中文表达
- 提升步骤、风险、验证项的扫读效率
- 保持与现有聊天流、按钮行为、提交流程兼容

## 非目标

本次不包含以下范围：

- 不统一移除所有 `OperateCard` 消费方的图标
- 不重构审批卡、工具调用卡、RAG 卡、设备动作卡的视觉样式
- 不改动计划评审卡的交互语义、提交协议和后端字段

## 设计方向

采用“专业简报卡”方向，整体气质偏克制、清晰、偏业务提案，而非操作日志。

核心体验原则：

- 先概览，后细节：标题与摘要先建立语境，再进入步骤和风险
- 强分区，弱装饰：通过版式、间距、分组建立层级，不依赖图标堆叠
- 中文业务表达优先：所有面向用户的静态文案统一切换为中文
- 重点突出：步骤与风险视觉权重高于次要说明项

## 信息架构

### 卡片整体结构

```text
┌──────────────────────────────────────────────┐
│ 标题                                          │
├──────────────────────────────────────────────┤
│ 摘要区                                        │
├──────────────────────────────────────────────┤
│ 执行步骤                                      │
│  01 步骤一                                    │
│  02 步骤二                                    │
├──────────────────────────────────────────────┤
│ 风险提示                                      │
│  • 风险一                                     │
│  • 风险二                                     │
├──────────────────────────────────────────────┤
│ 验证方式 / 待确认事项 / 方案把握度            │
├──────────────────────────────────────────────┤
│ 反馈输入框                                    │
│ 操作按钮区                                    │
└──────────────────────────────────────────────┘
```

### 标题区

- 仅展示 `data.title`
- 不展示头部图标
- 不在标题行展示 `summary`
- 仍保留折叠能力，但折叠箭头弱化处理，避免抢占标题视觉

### 摘要区

- 使用 `data.summary`
- 作为正文第一块区域展示
- 视觉上区别于普通段落，体现“本方案主要内容概览”
- 当 `summary` 为空时，整个摘要区不展示

### 中文分组映射

| 现有字段 | 展示文案 |
|----------|----------|
| `steps` | `执行步骤` |
| `risks` | `风险提示` |
| `verification` | `验证方式` |
| `open_questions` | `待确认事项` |
| `confidence` | `方案把握度` |
| `feedback` | `反馈意见` |

## 视觉方案

### 总体风格

- 卡片基底采用浅暖灰白，避免纯白信息墙
- 使用轻微边框和柔和阴影形成独立模块感
- 标题区域与正文通过留白分层，而不是用高对比底色硬切
- 风险区使用低饱和提醒色，不使用高亮警报红块，避免压迫感

### 标题样式

- 标题字号高于正文分组标题
- 标题字重中高，强调“当前评审对象”
- 单行优先，超长时允许省略，但保留良好呼吸感

### 摘要样式

- 采用独立浅底容器或轻描边容器
- 文本颜色弱于标题、强于辅助说明
- 行高适当放大，提升长句阅读性

### 分组样式

- 每个分组使用统一的中文小标题样式
- 分组之间通过垂直间距分隔，不依赖粗重分割线
- `执行步骤` 使用编号列表，替代普通黑点列表
- `风险提示` 使用更明显的块状列表或带强调边的容器

### 底部交互区

- 反馈输入与动作按钮独立为卡片下半部区域
- 输入框文案使用中文占位提示
- 按钮布局保持现有行为，但提升间距和视觉整洁度

## 交互设计

### 折叠行为

- 保留 `OperateCard` 的展开 / 收起交互
- 默认展开逻辑不变
- 头部点击区域仍可触发展开收起
- 折叠箭头改为低干扰状态，仅在可折叠场景中出现

### 内容展示规则

- 某一分组数据为空时，不渲染该分组
- 摘要为空时，不展示摘要块
- 把握度始终展示为中文标签加百分比

### 文案本地化

- 用户可见静态文案统一使用中文
- 包括分组标题、反馈占位文案、动作按钮文案附近的辅助说明
- 不修改后端协议字段，只修改前端展示文本

## 组件改造策略

### `OperateCard`

对基础组件只做最小必要增强，避免影响其他消费方：

- 允许头部图标在特定场景下不渲染
- 保持 `header.title` 作为头部唯一主要文本
- 让头部布局在“无图标”场景下仍然稳定对齐
- 保持 `header.description` 能力，以免破坏其他旧场景

### `PlanReviewCard`

评审卡自行承担主要版式改造：

- 不再将 `data.summary` 传入 `header.description`
- 将 `summary` 渲染到正文摘要区
- 将 `PlanList` 从简单 `ul/li` 升级为带中文标题的分组模块
- 将 `confidence` 与 `feedback` 统一纳入中文化内容区

### `PlanList`

建议扩展为更明确的分组组件：

- 支持中文标题
- `执行步骤` 使用序号样式
- 其他分组沿用普通列表或强调列表
- 空数据直接返回 `null`

## 数据流与兼容性

本次不改变任何已有提交流程：

- `handleDecision` 的行为保持不变
- `plan_interaction_response` 的结构保持不变
- `data.steps`、`data.risks`、`data.verification`、
  `data.open_questions`、`data.confidence` 继续沿用现有字段

因此，本次改造是纯前端展示层改造，不涉及后端接口兼容风险。

## 风险与约束

### 共享组件影响

`OperateCard` 是共享组件，审批卡、工具调用卡等场景也在复用。

约束策略：

- 基础组件只做向后兼容增强
- 场景化视觉重构尽量放在 `PlanReviewCard` 层完成
- 避免在共享样式中引入仅适用于计划评审卡的强绑定外观

### 本地未提交改动

当前工作区中 `PlanInteractionCards.tsx`、`PlanInteractionCards.module.less`、
`PlanInteractionCards.test.tsx` 已存在未提交修改。

实施时需要：

- 先审阅现有改动意图
- 采用最小侵入方式叠加设计改造
- 避免覆盖已有进行中的业务变更

## 验收标准

- 计划评审卡头部不再显示图标
- 头部第一行仅展示标题
- `summary` 出现在正文中，而非标题行
- `Steps`、`Risks`、`Verification`、`Open questions` 等英文标签全部替换为中文
- 分组层级清晰，步骤与风险信息扫读效率明显优于现状
- 现有提交、继续修改、退出计划模式等操作行为不受影响
- 其他 `OperateCard` 消费场景视觉与功能不发生异常回归

## 测试建议

### 组件测试

- 补充或更新 `PlanInteractionCards.test.tsx`
- 覆盖标题、摘要、中文分组是否正确渲染
- 覆盖空分组不展示
- 覆盖折叠状态下的基本展示

### 手工验证

- 在聊天页验证计划评审卡默认展开效果
- 验证长标题与长摘要时的换行或省略表现
- 验证移动端窄宽度下分组、输入框、按钮不拥挤
- 验证审批卡、工具调用卡等其它 `OperateCard` 使用场景未被破坏

## 推荐实施顺序

1. 为 `OperateCard` 增加无图标头部兼容能力
2. 重构 `PlanReviewCard` 的摘要区与中文分组结构
3. 在 `PlanInteractionCards.module.less` 中落地专属样式
4. 更新测试并完成手工验收
