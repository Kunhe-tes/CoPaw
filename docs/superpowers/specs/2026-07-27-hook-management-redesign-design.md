# Hook 管理页重设计

## 目标

将 Hook 管理从“左侧三层树 + 右侧长表单”改为以事件为入口的配置体验。用户应能先理解一个事件是否已配置、配置了什么，再按运行顺序编辑匹配条件和处理器。

本次只改变 Console 的信息架构和交互表达，不改变 Hook 配置的数据模型、保存接口或运行语义。

## 视觉方向

采用“运营总览 + 编排工作台”的混合布局：主页面优先帮助运营者判断 Hook 是否生效、哪些规则待发布及各生命周期事件的处理器覆盖；打开事件后以右侧大尺寸抽屉承载连续配置与测试。视觉语言沿用 Console 的蓝色品牌色和既有设计令牌，使用克制的状态色、细边框和有序连线来表达执行状态与处理器顺序，而不是新增一套独立主题。

总览从上到下依次是：标题与页面级操作、启用/最近发布状态横幅、已配置事件/处理器/待发布修改的指标、生命周期轨道、已配置事件列表与未配置事件入口。事件列表除摘要外，必须可直接看见处理器链、发布状态与编辑入口。

抽屉将编辑内容归为“基本设置、适用范围、处理器编排、测试与发布”四个区域。处理器链以顺序编号卡片呈现，选中的处理器在同一抽屉内展示其既有字段编辑器；测试执行记录和决策结果也在抽屉内显示。所有字段、提交时机、API 请求和运行语义保持不变。

## 用户流程

1. 用户打开 Hook 管理页，看到事件总览，而非事件/分组/处理器树。
2. 每个事件显示启用状态、分组数、处理器数和简短状态；未配置事件显示开始配置操作。
3. 用户选择新建事件，先选择事件，再选择空白事件或完整场景模板。
4. 用户在右侧抽屉编辑该事件：何时触发、适用范围、依序执行的处理器。
5. 用户可测试当前事件或一个处理器，并在同一抽屉查看结果。
6. 用户保存所有本地草稿；发生 revision 冲突时明确选择刷新并比较或覆盖保存。

## 信息架构

### 事件总览

- 顶部提供全局启用开关、保存状态和“新建事件”主操作。
- 页面主体为事件列表或卡片。每项展示事件名称、自然语言说明、已启用状态、分组数量和处理器数量。
- 已配置事件提供“编辑”；未配置事件提供“开始配置”。
- 不在总览展示树形层级、内部 Group ID 或处理器的所有字段。

### 新建事件

新建事件采用两步轻量流程：

1. 选择 Hook 事件。
2. 选择“从空白开始”或“从场景模板开始”。

场景模板应是完整的可编辑配置，包含推荐的匹配条件和处理器，而不仅是一个处理器类型。初始模板范围：会话启动检查、提示词预处理、工具调用审计、工具调用拦截、失败告警。

### 事件编辑抽屉

- 右侧抽屉保持事件总览可见；窄屏幕时全屏显示。
- 固定头部展示事件名称、启用状态、测试、保存与删除操作。
- 内容按运行时顺序组织：`何时触发` → `适用范围` → `依序执行的处理器`。
- 分组以人类可读名称展示，例如“所有工具”或“仅 Bash、Python”。内部 Matcher Group ID 和原始工具匹配条件置于高级编辑区。
- 处理器使用可排序卡片。卡片显示处理器类型、名称、关键摘要和失败策略；只有选中/展开后才显示命令、HTTP 或 Prompt 专属字段。
- 处理器排序必须映射到既有 `hooks` 数组顺序，不引入新的执行顺序模型。

## 状态与错误处理

- 编辑继续写入既有本地 draft，不改变请求时机。
- 总览和抽屉都要清晰提示未保存更改。
- 保存继续使用 revision 乐观并发控制。409 冲突提供“刷新并比较”与“覆盖保存”，不得静默覆盖。
- 测试仅作用于当前事件或当前处理器，结果留在抽屉结果面板，不跳转页面。
- 空状态明确说明该事件不会执行任何 Hook，并同时提供模板和空白两种开始方式。
- 继续保留现有的字段校验规则，包括命令参数、超时、会话快照、HTTP 地址、Prompt 内容和脚本工作目录限制。

## 组件边界

- `HookManagementPage`：加载/保存 draft、全局开关、事件总览和抽屉开闭状态。
- `EventOverview`：只负责事件摘要与进入编辑。
- `CreateEventFlow`：负责事件与模板选择，并输出一份符合既有配置模型的事件草稿。
- `EventEditorDrawer`：编辑单个事件，并向上提交事件级变更、测试和删除动作。
- `MatcherGroupEditor`：管理可读分组摘要及其高级匹配条件。
- `HandlerList` / `HandlerCard`：呈现、增删、排序和展开单个处理器。
- `ScenarioTemplate`：模板定义与向现有 `HookMatcherGroupDraft` / `HookHandlerDraft` 的映射；不改变 API 类型。

## 测试策略

- 单元测试：模板生成的事件草稿、分组/处理器新增删除、处理器排序和既有校验。
- 组件测试：事件摘要显示、空状态操作、抽屉编辑、未保存状态、模板选择与窄屏抽屉行为。
- 集成测试：保存成功、409 冲突交互、当前事件/处理器的手动测试入口及结果展示。

## 非目标

- 不调整后端 Hook 事件、配置 JSON 结构、Hook 执行顺序或运行时安全策略。
- 不新增用户自定义模板库、跨租户模板共享或批量编辑。
