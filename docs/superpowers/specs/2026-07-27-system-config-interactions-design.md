# 系统特性配置页交互与抽屉层级优化

## 目标

优化 `console/src/pages/SystemConfigPage` 的交互反馈与编辑层级，使管理员能快速识别可编辑配置、未保存修改和全局恢复操作的影响范围。

本变更仅覆盖前端页面、样式与测试；复用既有的 `DELETE /source-system-config/current` 恢复接口，不修改后端协议。

## 已确认的视觉方向

采用 A「定向强调」：在白底、高密度管理台中，交互目标仅在 hover、focus 或 active 时以浅蓝背景、主色边框、轻量阴影和方向箭头凸显。状态标签提供持久状态信息，避免整页持续高亮或布局位移。

页面遵循 Console 的白优先、紧凑管理台语言：不引入装饰渐变、悬浮专属的关键操作、重阴影或全局设计系统变更；所有新增运动限制在 150–220ms 的颜色、边框、阴影和 transform 过渡，并尊重 `prefers-reduced-motion`。

## 能力卡交互

`CapabilityGrid` 的卡片保留可访问的原生 `button` 语义。

- Hover：卡片使用主色边框、浅蓝功能底色和轻阴影；右侧方向图标提供“进入配置”的明确线索。
- Keyboard focus：使用高对比蓝色 focus ring，不依赖颜色作为唯一状态。
- Active：仅用短暂、轻微的视觉收紧反馈；不得改变卡片尺寸或导致网格重排。
- 内容：标题、状态标签、描述、来源和摘要继续保留，并为长文本保持截断或换行安全。

## 抽屉编辑区

抽屉从平铺表单改为分层编辑工作区：

1. 标题区展示“能力名称 + 配置”，并保留关闭操作。
2. 首个浅蓝摘要区展示来源状态、高影响标记（如适用）、能力说明和“修改需在页面底部统一保存”的生效规则。
3. 编辑项按用户意图分为紧凑的功能组；每组有标题、项目数或简短元信息，设置行内保留标题、说明和控制器。
4. 高级参数以明确的可展开行收敛，避免默认占用首屏注意力。
5. 抽屉底部显示未保存状态，并提供“关闭 / 回到页面保存”的语境提示；不在抽屉内新增与页面级保存冲突的 API 调用。

所有现有开关、禁用、加载、关闭和统一保存语义保持不变。高影响开关的现有二次确认继续有效。

## 恢复默认设置

底部的旧“删除”按钮实际执行的是全局恢复默认，不再使用删除文案或删除图标语义。

- 新按钮名称：`恢复默认设置`。
- 操作区增加简短说明：该操作将清除当前系统的全部自定义配置并恢复继承默认值。
- 点击按钮仅打开确认弹窗，不立即调用 API。
- 弹窗标题：`恢复当前系统的默认设置？`。
- 弹窗正文明确说明：确认后会移除已保存的自定义覆盖，同时丢弃当前未保存草稿；无法从此页撤销。
- 确认按钮：`恢复默认设置`，使用危险操作层级；取消按钮保留现状。
- 确认后复用 `deleteCurrent()`，重新加载当前记录与有效配置，并将草稿、提示词片段同步为恢复后的默认态。

## 错误与状态

- 按钮在加载、保存、当前记录未就绪或已处于默认态时禁用。
- 确认进行中显示 loading，防止重复提交；失败时保留现有错误告警与草稿，不关闭页面上下文。
- 恢复成功后关闭弹窗、刷新元数据与能力状态，并显示“当前系统配置已恢复默认态”。
- 所有交互控件维持可见 focus、禁用和加载状态；动态状态不只靠颜色表达。

## 测试

为 `SystemConfigPage` 增加或更新测试：

1. 底部显示“恢复默认设置”而不是“删除”。
2. 点击恢复按钮只打开确认弹窗，不调用 `deleteCurrent`。
3. 确认后调用 `deleteCurrent`，重新加载配置，并将草稿恢复为默认态。
4. 取消确认不会调用 API，也不会丢弃未保存草稿。
5. 抽屉继续可从能力卡打开，并保留统一保存的提示与高影响状态。
6. 为能力卡与抽屉的新增结构补充必要的可访问查询断言。

## 非目标

- 不改变 source 系统切换、权限、API 请求参数或后端默认值规则。
- 不新增独立的抽屉保存接口或抽屉内局部持久化。
- 不做 Console 其他页面的通用视觉重构。
