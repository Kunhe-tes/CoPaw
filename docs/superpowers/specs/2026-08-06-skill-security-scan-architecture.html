一张图看架构

目标态主链路只保留三类核心对象：`ScanContext` 承载输入，`Finding` 承载证据，`Decision` 承载准入结论；MVP 可先复用现有 `SkillFile` 和同步扫描入口逐步演进。

分层设计

层级 职责 设计要点
L1 入口接入层 收口聊天创建、ZIP 上传、Market 上架、租户安装和存量回扫。 所有入口先进入草稿区或隔离区，不允许未扫描内容进入运行目录。
L2 包体与上下文层 安全解包，目标态生成统一 `ScanContext`。 MVP 先保证现有 ZIP 外来包只能进入隔离区并完成安全解包校验，覆盖路径穿越、符号链接、文件数、单成员体积和总解压体积阈值；TAR 等其他包格式后续按同一边界扩展，再提取文件、声明、权限、依赖、MCP、哈希、版本、租户和来源信息。
L3 基础静态检测层 高置信规则与 AST 行为检测。 覆盖 Prompt Injection、命令注入、密钥、敏感路径、外联、混淆和危险函数。
L4 语义与行为分析层 识别自然语言恶意意图、权限不一致和数据流风险。 引入 LLM 语义复核、source/sink 污点链路、SkillSpector 二级验证。
L5 供应链与情报层 依赖漏洞、恶意包、许可证、域名/IP、哈希和作者信誉。 结合 pip-audit、npm audit、OSV、SBOM/AI-BOM 与威胁情报回扫。
L6 风险决策与准入层 聚合 Finding，输出准入 Decision。 Critical 阻断，High 默认阻断或复核，Medium 要求修复，Low/Info 记录放行。
L7 运行时与运营闭环层 发布后持续约束和回扫。 复用 Tool Guard、File Guard、process limits、租户路径边界、版本差分和高危下架。

关键选型

主链路

增强 CoPaw 现有 `SkillScanner`，保持 SWE、Market、Console 准入路径可控。

开源引擎

SkillSpector / Cisco Skill Scanner 做高风险二级扫描，Agent-Scan / MCP-Scan 做巡检和专项扫描。

运行时兜底

静态扫描之外，继续依赖 Tool Guard、File Guard、租户路径边界、沙箱和审计。

落地节奏

阶段一：准入可用

安全解包、基础规则、AST 行为、统一 Finding、阻断/警告/白名单、复用现有 Console 安全页完成最小风险可见性。

阶段二：检测增强

语义复核、污点追踪、依赖 SCA、开源引擎二级扫描、Market 上架强审核。

阶段三：运营闭环

版本差分、存量回扫、威胁情报、AI-BOM、动态沙箱、高危下架与影响面排查。

评审关注点

  • 是否认可“CoPaw 自研主链路 + 开源二级验证”的总体方向。
  • 是否认可七层职责拆分，以及 L6 才做准入决策的边界。
  • 是否将动态沙箱放在第二或第三阶段，而不是首版强依赖。
  • 是否需要为高风险租户、Market 上架和本地开发配置不同 scan profile。
