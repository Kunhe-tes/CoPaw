Skill 安全扫描详细设计

本文档承接精炼版架构稿，展开技术选型、开源框架接入、准入策略、链路设计与实施优先级。 精炼版主文档见 2026-08-06-skill-security-scan-architecture.html。

CoPaw 内部 Skill 安全扫描详细设计
核心原则
不只扫代码，要扫声明、权限、依赖、数据流与运行行为

SWE 创建链路 + Market 上架链路 + 运行时治理

总体架构图

这张图展示 CoPaw 的 Skill 安全链路主干：入口收口、上下文构建、多引擎扫描、风险决策和输出治理。工程设计上再向下拆成七个层次，分别承担接入、解析、检测、决策、执行和运营职责。

设计结论

这套方案不是单纯增强一个 regex 扫描器，而是把 Skill 当作供应链包来处理。 它的最小闭环应该覆盖五类对象：包体、声明、代码、依赖、运行行为。

对 CoPaw 来说，现有 `scan_skill_directory()` 可以继续做统一入口，但它必须升级为一个编排层： 先做安全解包和上下文归一化，再按分析器并行执行，最后把结果汇总到统一的风险决策中心。

推荐方向 先把“高置信阻断 + 人工复核 + 可解释输出”做实，再逐步加入污点追踪、语义分析和动态沙箱。
不要一开始就做的事 不建议把外部开源扫描器直接塞进主安装链路里当唯一判定来源。更稳的方式是把它们作为可插拔引擎，统一收敛到同一份 Finding Schema 和准入策略。

分层架构设计

Skill 安全扫描按七层设计，每层只解决一类问题，并以目标态的 `ScanContext`、`Finding`、`Decision` 三类对象衔接。MVP 阶段可先复用现有 `SkillFile` 与同步扫描入口，在不改变调用方契约的前提下补齐安全解包、包体检测和 AST 检测；后续再收敛到完整 `ScanContext`。

层级 核心职责 输入 / 输出 CoPaw 落点
L1 入口接入层 收口所有 Skill 来源，确保任何创建、上传、分发、安装动作都不能绕过扫描。 输入：聊天生成草稿、ZIP 包、Market 包、租户技能目录。输出：扫描任务与隔离区 artifact。 SWE `skills_manager`、Market `marketplace/service.py`、Console 创建与上传入口。
L2 包体解析与上下文层 安全解包并逐步建立统一扫描上下文，解决 Zip Slip、Zip Bomb、符号链接逃逸和文件清单可信性问题。 输入：原始包或草稿目录。MVP 输出隔离区目录、安全文件清单和现有 `SkillFile`；目标态输出 `ScanContext`、文件清单、哈希、manifest、权限、依赖、租户与版本元数据。 新增 package normalizer / safe unpack helper，复用现有 `SkillFile` 与内容 hash 能力。
L3 基础静态检测层 用高置信、低成本规则拦截明确风险，包括 Prompt Injection、命令注入、密钥、敏感路径、外联和混淆。 输入：MVP 为现有 `SkillFile` 列表，目标态为 `ScanContext.files`。输出：规则类 `Finding`，包含文件、行号、证据、修复建议。 现有 `PatternAnalyzer`、YAML 规则、`ScanPolicy`，新增包体规则和 AST 行为 analyzer。
L4 语义与行为分析层 处理 Skill 特有风险：自然语言隐藏指令、权限与功能不一致、客户/租户数据 source 到网络、日志、文件、记忆、触达工具的 sink 链路。 输入：声明、代码行为摘要、权限声明、工具/MCP 能力。输出：语义风险、污点链路、权限一致性结论。 新增 `semantic_analyzer.py`、`taint_flow_analyzer.py`；SkillSpector 可作为 strict profile 二级引擎。
L5 供应链与情报层 识别依赖漏洞、恶意包、typosquatting、许可证风险、可疑域名/IP、包哈希和作者信誉。 输入：依赖文件、lock、外联目标、包哈希、SBOM/AI-BOM。输出：供应链 Finding、回扫索引、资产清单。 `DependencyAnalyzer` + pip-audit / npm audit / OSV 可选后端；AI BOM / SBOM 用于运营回扫。
L6 风险决策与准入层 聚合多引擎发现，结合严重级别、置信度、租户策略、Skill 来源和运行权限，做阻断、复核、修复、警告或放行。 输入：多类 `Finding`。输出：`Decision`、风险评分、用户风险卡片、审核任务、白名单/例外记录。 扩展现有 block/warn/off、白名单、数据库历史和 Console 安全页。
L7 运行时与运营闭环层 补齐静态扫描无法覆盖的风险，执行前后通过 Tool Guard、File Guard、process limits、路径边界、出网策略和审计持续约束。 输入：已发布 Skill、运行调用、工具链路、版本变更、情报更新。输出：运行审计、版本差分、存量回扫、高危下架和影响面排查。 `tool_guard_mixin.py`、tenant path boundary、process limits、Market 回扫任务、审计与复核后台。
层间契约 L1/L2 只负责生成可信输入，目标态形成统一扫描上下文；L3/L4/L5 只产出证据；L6 才做准入决策；L7 负责发布后的持续治理。
关键边界 扫描器不能在真实租户运行目录中直接解包和执行外来内容；动态验证只能在隔离沙箱中使用模拟凭证、模拟客户数据和受控网络。

模块边界

1. 安全解包器

目标态处理 ZIP/TAR 等外来包；MVP 先收敛现有 ZIP 导入链路，负责 Zip Slip、Zip Bomb、符号链接、文件数、单成员体积和总解压体积阈值控制。

2. 上下文构建器

把文件、声明、权限、依赖和业务语义整理成统一扫描上下文，供所有引擎复用。

3. 多引擎扫描层

规则、AST、污点、SCA、语义、情报并行跑，避免把所有判断压在单一正则上。

4. 风险决策中心

把技术发现转换成阻断、复核、修复或放行，不直接把原始扫描结果暴露给用户。

5. 发布与安装闸口

覆盖 SWE 创建、Market 上架和租户安装，任何入口都不能绕过扫描结果。

6. 运行时治理

Tool Guard、File Guard、process limits、路径边界和审计一起兜住静态扫描之外的风险。

技术选型

技术选型分为两层：CoPaw 内部主链路优先复用现有 Python / FastAPI / Market / Console 栈； 参考文档中的开源框架作为可插拔扫描引擎、交叉验证工具或运行时治理参考接入。

CoPaw 内核选型

能力域 推荐技术 选择理由 落地位置
扫描编排 Python + 现有 `SkillScanner` / `scan_skill_directory()` 当前 SWE 与 Market 已经在 Skill 创建、导入、上架路径调用扫描入口，继续增强可减少接入面变化。 `src/swe/security/skill_scanner/`，后续抽出 SWE 与 Market 共享内核
规则扫描 YAML 规则 + Python regex + 策略覆盖 仓库已有 `PatternAnalyzer`、规则目录和 `ScanPolicy`，适合高置信、低成本地拦截 Prompt Injection、命令注入、密钥和外联风险。 `rules/signatures/*.yaml`、`scan_policy.py`
包体安全 Python `zipfile` / `tarfile` 安全解包 + MIME/文件头识别 上传包必须先防“解析即受害”，重点处理 Zip Slip、Zip Bomb、符号链接逃逸、可执行二进制和隐藏文件。 新增 `package_analyzer.py` 与安全解包 helper
代码行为分析 Python `ast` + Shell/JS 轻量模式扫描 首版优先覆盖 Python 技能中的 `eval`、`exec`、`subprocess`、敏感路径、容器逃逸和网络发送，避免一开始引入重型 SAST。 新增 `ast_behavior_analyzer.py`
污点追踪 轻量 source/sink 图谱 + 规则化数据流 SkillSpector 和 Agent-Scan 的共同经验是要看数据从哪里来、流向哪里；CoPaw 可先做函数级启发式追踪，再演进到跨文件流。 新增 `taint_flow_analyzer.py`
依赖与供应链 自研依赖清单解析 + 可选 pip-audit / npm audit / OSV 首版先解析 `requirements.txt`、`package.json`、lock 文件并生成 SBOM 雏形；联网漏洞库查询作为可配置增强项。 新增 `dependency_analyzer.py`，扫描结果写入统一 Finding
语义安全 LLM-as-a-judge 可插拔引擎 自然语言恶意意图无法靠正则覆盖；LLM 分析器只做复核和解释，不单独决定阻断，避免模型误判直接影响发布。 新增 `semantic_analyzer.py`，默认可关闭或仅 strict profile 启用
动态沙箱 Kubernetes Job / 容器隔离 + 受控网络代理 项目部署环境是 Kubernetes，多实例场景下用一次性 Job 跑高风险样本更贴近生产；本地开发可降级为禁网临时目录执行。 后续新增 sandbox service，与 scan task 异步编排
任务与历史 FastAPI 异步任务 + MySQL 扫描历史 仓库已有数据库化 `swe_skill_scan_history` 设计，继续扩展为扫描任务、版本指纹、决策和人工复核记录。 `src/swe/app/routers/config.py` 与扫描 history store
Console 展示 现有 React / TypeScript 安全配置页扩展 复用已有 `securityApi`、block/warn/off、白名单和历史列表，新增风险卡片、引擎详情、复核状态和版本差分。 `console/src/api/modules/security.ts` 与 Security 页面
首版必选 Python 扫描编排、YAML 规则、包体安全解包、AST 行为分析、统一 Finding Schema、数据库历史与复用现有 Console 安全页的最小风险可见性。
增强可选 LLM 语义复核、OSV/pip-audit/npm audit、SkillSpector/Agent-Scan/MCP-Scan、Kubernetes 动态沙箱、SARIF 导出。

参考文档中的开源框架选型

开源框架 / 工具 定位 建议接入方式 不直接作为唯一主链路的原因
NVIDIA SkillSpector Skill 包语义安全、权限一致性、AST 行为、污点链路与风险评分的交叉验证引擎 作为 strict profile 的二级扫描器接入，重点用于 Market 上架、高风险权限、外部来源 ZIP 和人工复核前预判。 适合作为强校验引擎，但需要把输出映射到 CoPaw Finding Schema，并处理模型依赖、误报复核和性能开销。
Snyk Agent-Scan 本机 Agent / MCP / Skill 资产盘点与 Toxic Flow 风险巡检工具 用于运维巡检、企业终端治理、运行环境基线检查，发现已安装 MCP Server、工具投毒和有毒流组合。 它更偏终端资产发现和远端分析，不适合作为 CoPaw 聊天创建或 ZIP 上传的同步准入主引擎。
Invariant MCP-Scan MCP Server 工具描述投毒、Prompt Injection、Toxic Flow 专项扫描 当 Skill 绑定 MCP 工具、上传 MCP 配置或 Market 分发 MCP Server 时触发专项扫描。 扫描对象聚焦 MCP，不覆盖完整 Skill 包体、依赖、租户目录和 CoPaw 业务权限。
Cisco Skill Scanner Skill 包规则、YARA、行为数据流、LLM-as-a-judge、SARIF/JSON 报告生成 作为中长期主扫描引擎候选之一，以 CLI/服务插件方式接入静态扫描编排器，先在离线批量回扫中验证效果。 需要确认部署成本、规则可控性和输出稳定性；接入前仍需 CoPaw 自己完成安全解包、租户上下文和准入决策。
Cisco MCP Scanner 远程或托管 MCP Server 的认证、instructions、prompt/resource、依赖漏洞和 YARA 检测 用于 MCP 市场、远程 MCP 接入和托管 MCP 复检，与 MCP-Scan 形成互补。 同样是 MCP 专项工具，不能替代 Skill 生命周期扫描和运行时 Tool Guard。
Cisco DefenseClaw Agent 运行时策略网关与人工确认机制参考 作为 CoPaw 运行时治理设计参考，对齐 Tool Guard、File Guard、外联控制、审批和审计链路。 更适合借鉴架构模式，不建议直接替换现有 `tool_guard_mixin.py` 与审批体系。
Cisco AI BOM / SBOM 工具链 Skill、Agent、MCP、模型、依赖、外部 API 的资产清单与持续回扫基础 用于生成 CoPaw Skill AI-BOM，支撑版本差分、依赖漏洞回扫、威胁情报命中和审计报表。 资产清单能支撑运营，但本身不是阻断引擎；仍要接入风险决策中心。
pip-audit / npm audit / OSV Python / Node 依赖漏洞检测 作为 `DependencyAnalyzer` 的可选后端，standard profile 做离线解析，strict profile 联网查询漏洞库。 依赖扫描只覆盖供应链 CVE，不覆盖 Prompt Injection、恶意语义、权限越界和运行行为。
选型结论 首版主链路采用 CoPaw 自有 `SkillScanner` 增强，保证准入路径、租户隔离、历史记录和 Console 体验可控； SkillSpector 与 Cisco Skill Scanner 作为高风险样本二级扫描器候选； Agent-Scan、MCP-Scan、Cisco MCP Scanner 用于运行环境与 MCP 专项巡检； AI BOM / SBOM 工具链服务于长期运营回扫。

准入策略

级别 建议决策 典型触发
Critical 阻断 恶意代码、反向 shell、C2、凭证窃取、Zip Slip、容器逃逸、客户数据外发
High 默认阻断，必要时人工审批 Prompt Injection、高风险权限、动态库、混淆、未知外联、敏感路径访问
Medium 要求修复或复核 硬编码密钥、过宽依赖、低中危 CVE、权限说明不完整
Low / Info 记录后放行 低风险提示、文档质量问题、可解释但不影响准入的轻微告警

链路设计

入口
创建 / 上传 / 上架 / 安装都先落到草稿或隔离目录 先归一化再扫描，不允许把未审的内容直接进入可执行区或可分发区。
扫描
规则、AST、污点、SCA、语义分析并行执行 让不同分析器各做一件事，最后再由决策层合并结论，减少单点误判。
决策
把结果转成可解释的风险卡片和状态机 用户看到的是“为什么被挡”和“怎么改”，平台看到的是证据、严重度和审批状态。
运营
版本差分、威胁情报回扫和审计留痕长期保留 让后来新增的规则、CVE、恶意包情报可以回头重新审旧版本。

实现优先级

第一阶段 在现有 `scan_skill_directory()` 上补齐包体安全解包、声明层扫描、AST 扫描和统一风险输出。
第二阶段 加入污点追踪、依赖 SCA、语义复核与动态沙箱，把高风险样本的复核效率做上去。
第三阶段 打通 SWE、Market、Console 的统一策略、版本差分和运营回扫，形成持续治理闭环。
最终状态 Skill 不再是一个普通文件，而是一个被扫描、被解释、被审计、被运行时约束的高权限资产。
