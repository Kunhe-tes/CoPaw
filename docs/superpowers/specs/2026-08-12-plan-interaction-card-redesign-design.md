# 计划交互卡片视觉重构设计

**日期：** 2026-08-12
**范围：** Chat 中 `ask_plan_clarification` 与 `submit_proposed_plan` 对应的前端交互卡片

## 目标与边界

把计划澄清卡和计划审核卡统一为轻量、清晰的企业级任务面板。设计参考确认后的 UI：强调独立选项、明确的已选状态、充分留白和收束的 Footer。

澄清卡继续在聊天输入区内嵌并替换普通输入器；审核卡继续出现在助手消息内。不引入遮罩、全屏弹窗、后端契约或交互流程变化。

## 当前实现

- `PlanClarificationCard` 在 `ActivePlanInteractionComposer` 中渲染；它负责单选、多选、文本、分页表单、键盘操作和提交 payload。
- `PlanReviewMessageCard` 在助手运行时消息中渲染；待确认状态提供继续修改、执行和退出计划模式三种决策，已提交状态展示只读快照。
- 两类卡片共用 `PlanInteractionCards.module.less` 的本地视觉变量，并已有键盘、状态与提交流程测试。

## 视觉系统

在聊天局部样式中定义并复用下列语义角色，不改变管理控制台或对话工作区的全局主题：

| 角色 | 值 | 用途 |
| --- | --- | --- |
| 面板 | `#FFFFFF` | 卡片、选项和输入表面 |
| 默认边界 | `#E5E7EB` | 卡片、选项和输入的常规边框 |
| 弱表面 | `#F7F9FC` | 非关键分组与次级信息 |
| 主文字 | `#111827` | 标题与核心正文 |
| 次文字 | `#4B5563` | 说明与列表内容 |
| 弱文字 | `#8A94A6` | 分页、快捷键和占位文案 |
| 主色 | `#3769FC` | 主按钮、已选状态和焦点 |
| 主色弱化 | `#EEF4FF` | 已选卡片背景 |

卡片圆角为 12px，控件圆角为 8px，默认使用一像素中性边界和轻微表面阴影。动画只保留 160ms 的进入与状态过渡，并遵守减少动态效果偏好。

## 澄清卡

1. 顶部使用 16–17px 问题标题；多字段表单保留右上角分页及前后翻页控制，但降低其文字和图标权重。
2. 每个选项成为最小 52px 的独立选择卡，卡间距为 8px；编号成为 28px 方形视觉锚点。
3. 普通状态使用白底与中性边界；悬停使用弱表面；已选状态同时使用浅蓝底、主色边界、蓝色编号块和右侧圆形 Check。
4. 焦点仅通过可见焦点环表达，不能使用与选中相同的 Check 或额外方向图标，确保鼠标、键盘与已选状态可区分。
5. 自定义回复保留现有行为：顶层多选可与文字叠加，顶层单选输入文字会清除单选。输入框默认是低权重补充区域，输入或聚焦时才显示主色边界与焦点环。
6. Footer 用中性分隔线划分：左侧键盘提示，右侧描边“退出 ESC”与蓝色“提交 ↵”。多步骤时主按钮显示“继续”，最终步骤显示“提交”。

键盘行为、`aria-current`、`aria-pressed`、`role=region`、禁用条件、表单 payload 和一次性提交防护保持不变。

## 计划审核卡

1. 标题下展示简洁状态，例如“计划待确认”；已提交快照继续展示既有的决定结果。
2. 摘要作为弱表面信息块；“执行步骤”“风险提示”“验证方式”作为独立、可换行的内容分组，减少连续的重边框。
3. 活跃审核卡改为内容自适应高度，保留合理最大高度和溢出滚动，避免当前固定高度在短计划中产生大量空白。
4. 全部操作统一为中文，并固定层级与顺序：`继续修改`（低强调）→ `退出计划模式`（次按钮）→ `开始执行`（唯一蓝色主按钮）。
5. 点击决策后继续禁用全部操作，防止重复执行；“继续修改”和“退出计划模式”不发送原本不应发送的聊天提交事件。

## 实现范围

- 修改 `console/src/pages/Chat/components/PlanInteractionCards.tsx`：仅调整选项、标题、Footer 和审核卡操作区的表现与文案；不改状态机或事件 payload。
- 修改 `console/src/pages/Chat/components/PlanInteractionCards.module.less`：替换局部视觉变量和响应式布局，补齐已选、焦点、悬停、禁用、深色模式与减少动态效果。
- 修改 `console/src/pages/Chat/components/PlanInteractionCards.test.tsx`：保留行为测试，更新文案断言，新增状态可区分、中文操作和不固定空高度的回归断言。

不修改 `src/swe/agents/tools/planning.py`、消息元数据结构、计划服务、聊天提交协议或其他页面。

## 验收标准

- 澄清卡在桌面与窄屏中保持内嵌，不出现蒙层或遮挡聊天上下文。
- 普通、悬停/焦点、已选和禁用选项在视觉及辅助技术语义上可明确区分。
- 蓝色仅用于已选、焦点和主操作；默认边框不使用高饱和蓝。
- 审核卡三个操作为中文，只有“开始执行”是主要按钮。
- 单选、多选、文本、表单分页、键盘导航、提交 payload、退出、继续修改、执行、退出计划模式与已提交快照维持当前行为。
- 目标 Vitest 测试通过；改动通过类型检查与样式构建中对应的校验。

## 风险与缓解

- 调整 DOM 结构可能影响无障碍名称与既有测试；在保留角色和事件逻辑的前提下，逐项更新语义断言。
- 审核内容可很长；使用换行、最小宽度和受限滚动，避免操作区被挤出视口。
- 深色模式现由本模块覆盖；同步更新语义变量，而非在新规则中散落固定颜色。
