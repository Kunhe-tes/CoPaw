# 场景预设目录与会话资源注入设计

## 目标

为每个 Source 提供由管理员维护的“能力域 → 能力 → 场景预设”目录。终端用户在新会话中选择场景后，编辑并提交提示草稿；系统在首次提交时安全地把场景关联的市场 Skill 和 MCP 服务注入当前 Chat，而不在用户消息中暴露 `@skill` 或 `@server`。

## 范围与术语

- 目录节点均具有 Source 内全局、不可变且不复用的 ID；名称只是显示字段。
- 目录是严格树：能力域包含能力，能力包含场景；节点不共享父级。
- 初始目录为空，`three_level_ai_ui_draft_v2.html` 仅作视觉参考，绝不导入为数据。
- 市场资源绑定使用稳定市场 ID，并在新 Chat 的首次提交时解析当时最新可用版本。

## 目录管理

目录存储在 Source 作用域的数据库表中，按同级 `sort_order` 有序。管理员（`isSuperManager || manager`）可创建、编辑、启停、排序和移动节点；仅叶节点可删除。相同父级下，去除首尾空格且大小写不敏感后的名称唯一。移动保留节点 ID、文本与绑定，并将节点置于目标父级末尾。

管理页为一张三级树。空目录只提供“新建能力域”；场景详情抽屉编辑提示草稿并绑定零或多个市场 Skill、零或多个完整市场 MCP 服务。失效绑定保留最后可见标签和失效原因，管理员可移除或替换，但无需先修复才能保存场景。

## 新会话交互

欢迎页仅在存在完整且启用的三级路径时显示选择器；否则保持普通自由输入。初始仅展开排序首位的能力域与能力，且不自动选中场景、不填充文本。

选中场景后，编辑器以不可编辑的原子前缀 `@能力名称` 开头，后接可任意修改或清空的提示草稿。该前缀不含能力域，也不呈现关联 Skill/MCP 或可移除资源入口。删除整个原子前缀会取消场景选择与待提交绑定；只提交该前缀是有效请求。首条用户消息一经提交，场景和 Agent 锁定；切换场景需新建 Chat。

## 首次提交、快照与安全

前端只提交 `scenario_preset_id`，不在点击场景时解析资源。后端于首条消息提交时在同一原子操作中：重新验证场景有效性和可见性、解析市场资源、优先匹配租户/Agent 常驻资源、仅在缺失时建立本 Chat 临时视图，并把结果写入既有 `ChatSpec.meta`。同一 Chat ID 的重复提交复用该快照；已有 Chat 恢复时只恢复快照，绝不查询市场最新版本。

Skill 在运行时通过与现有 `@Skill` 等价的可信上下文指令注入；MCP 按完整服务绑定、在首次提交发现并冻结可调用工具集。MCP 凭证只能引用当前租户已有凭证，不能复制、保存或跨租户传递。所有资源仍经过普通市场可见性、Tool Guard、审批和凭证校验。

无法解析的单项资源不会中断场景消息；系统以剩余资源执行，终端用户不接收部分降级提示。若场景本身在提交前已删除或停用，后端拒绝初始化，保留提示草稿并清除过期选择。临时视图在 Chat 永久删除时清理；可恢复删除期间保留。仅输出不含草稿、技能内容、MCP 配置或凭证的结构化应用日志。

## 数据流

```text
管理页 ──管理员 CRUD──> Source 场景目录
新会话 ──有效目录只读──> 选择场景 + @能力原子标记 + 可编辑草稿
首次提交 ──scenario_preset_id──> 后端重校验/资源解析/ChatSpec.meta 快照
后续消息或恢复 ──快照──> 既有上下文引用、Agent、Tool Guard、审批链
```

## 验收标准

1. 空目录不影响普通新会话；管理员可从零建立有效三级路径。
2. 终端用户只能看到二级能力原子标记和草稿，不能看到或删除资源绑定。
3. 资源从首次提交才解析，且同一 Chat 的重试和恢复不会重新解析市场最新版本。
4. 缺少常驻资源时资源只在当前 Chat 临时可用；租户/Agent 配置及其凭证永不被写入或复制。
5. 失效资源降级不中断用户请求，但目录管理页可诊断和修复。
6. 所有 Source、角色、机构可见性、凭证、Tool Guard 和审批边界继续生效。
