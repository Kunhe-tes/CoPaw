# 场景预设管理 UI 重设计方案

## 1. 背景与目标

当前场景预设管理页使用 Ant Design `Tree` 展示三级节点，并通过 `Drawer` 编辑节点。参考图采用分层表格，能更直接地比较名称、描述和操作，但当前实现的树节点操作分散、编辑上下文容易被抽屉打断。

本次设计采用“分层表格 + 固定右侧详情面板”：

- 左侧负责高密度浏览、展开/收起、排序和新增；
- 右侧负责当前节点的配置编辑与保存；
- 保留现有三级层级：能力域 → 能力 → 场景；
- 面向管理员维护几十条以内的目录，不引入搜索、分页和批量操作；
- 详情面板只负责配置保存，不加入试运行或预览。

## 2. 设计原则

1. **列表优先**：首屏先看到目录全貌和当前状态，避免用大卡片稀释信息密度。
2. **上下文稳定**：点击行只切换右侧详情，不打开/关闭抽屉，不改变列表位置。
3. **操作就近**：新增能力域放在页头；新增能力/场景放在对应父级行；排序只作用于同级。
4. **状态明确**：启用/停用、加载、保存中、资源不可用和未保存修改都必须有明确反馈。
5. **保持业务契约**：不改变现有 API、路由、权限、节点层级规则和资源绑定语义。

## 3. 页面结构

### 3.1 页面头部

- 标题：`场景预设管理`
- 描述：`按能力域、能力、场景维护新会话入口。`
- 右侧主操作：`+ 新建能力域`
- 不增加搜索框、筛选器、统计卡片或批量工具栏。

### 3.2 主工作区

桌面端采用左右两栏：

- 左侧列表：约 65%–70% 宽度，最小宽度保证四列不被截断；
- 右侧详情：约 300–360px，固定在页面内，不使用 Drawer；
- 容器使用白色表面、1px 中性边框和轻微阴影，遵循 `console/DESIGN.md` 的管理端基线。

列表列：

| 列 | 内容 |
| --- | --- |
| 名称 | 展开/收起、层级缩进、类型图标、名称 |
| 描述 | 能力域/能力显示子节点数量；场景显示描述或提示草稿摘要 |
| 状态 | 启用、停用或部分停用 |
| 操作 | 新增子节点、同级上移/下移、更多菜单 |

节点行规则：

- 能力域：文件夹图标；可新增能力；
- 能力：能力图标；可新增场景；
- 场景：文档图标；可编辑和配置资源；
- 默认展开全部已有节点，保留用户手动展开/收起状态；
- 当前选中行使用浅蓝背景和左侧 2px 强调边界；
- 拖拽排序可作为后续增强，本次先实现明确的上移/下移，避免与点击行冲突。

### 3.3 详情面板

未选择节点时显示空状态：`选择左侧节点开始编辑`。

选择节点后显示：

- 节点类型、名称和面包屑路径；
- 名称输入框；
- 启用开关；
- 场景节点额外显示：
  - `提示草稿` 多行输入；
  - `关联 Skill` 多选；
  - `关联 MCP 服务` 多选；
  - 资源绑定说明；
- 底部固定 `保存更改` 主按钮；
- `更多` 菜单提供移动和删除，危险动作二次确认。

详情面板不包含试运行、聊天预览或独立发布流程。

## 4. 交互流程

### 4.1 选择与编辑

1. 点击任意节点行，右侧面板切换到该节点；
2. 修改字段后进入“未保存”状态，保存按钮可用；
3. 切换到其他节点或离开页面时，若存在未保存修改，提示“保存 / 放弃”；
4. 保存成功后保留当前选中节点，并刷新列表中的名称、描述和状态；
5. 保存失败时保留编辑内容，展示错误信息，不关闭详情面板。

### 4.2 新建

- `新建能力域`：页头按钮触发轻量表单；
- `新建能力`：能力域行内按钮触发；
- `新建场景`：能力行内按钮触发；
- 创建成功后刷新目录，并自动选中新建节点；
- 名称为空时阻止提交并在字段下方提示。

### 4.3 排序与移动

- 上移/下移按钮仅调整同一 `parent_id` 下的相邻节点；
- 到达边界时按钮禁用；
- “移动”放入更多菜单，仅允许移动到合法父级；
- 移动成功后刷新列表并选中移动后的节点；
- 有子节点的父级不可删除，详情面板展示原因。

### 4.4 资源绑定

- 保留现有 Skill / MCP 稳定 ID 绑定方式；
- 资源加载失败时禁用保存，避免覆盖未知绑定；
- 已绑定但当前不可用的资源仍显示，并标记“当前不可用”；
- 绑定变更仅在点击保存后提交。

## 5. 状态与反馈

- 加载：列表区域显示骨架或 `Spin`，详情区不闪烁；
- 空数据：显示说明和 `新建能力域` 主按钮；
- 加载失败：页面级错误提示，提供重试；
- 保存中：保存按钮进入 loading，避免重复提交；
- 保存成功：使用现有消息机制提示 `场景预设已保存`；
- 停用：列表状态列显示“停用”，行仍可编辑；
- 删除：危险确认，明确不可恢复及子节点限制；
- 未保存：切换节点前二次确认；
- 键盘：表格行、按钮、输入控件均可聚焦，焦点状态符合管理端蓝色 focus ring 规范。

## 6. 技术边界

- 页面继续使用 React + TypeScript + Ant Design；
- 优先在现有 `console/src/pages/Control/ScenarioPresets/index.tsx` 内拆分局部展示组件与样式模块；
- 继续复用 `scenarioPresetApi`、`marketApi`、`marketMcpApi` 以及现有错误处理；
- 不修改 API 类型、请求路径、请求参数、权限和路由；
- 不扩展全局设计 token，只使用现有 Console 管理端 token；
- 如需样式文件，使用页面级 CSS Module/Less，避免新增全局样式。

## 7. 验收标准

1. 首屏同时看到三级目录的主要结构和当前节点配置；
2. 点击行不打开 Drawer，右侧面板稳定切换；
3. 能力域、能力、场景的新增入口位置与层级匹配；
4. 上移/下移只影响同级节点，边界状态正确；
5. 场景可编辑提示草稿、Skill、MCP 和启用状态，并保持现有保存语义；
6. 资源加载失败不会覆盖已有绑定；
7. 空、加载中、失败、保存中、保存成功、停用、删除确认和未保存离开均有可识别状态；
8. 长名称、长描述和不可用资源不会破坏列布局；
9. 现有场景预设相关测试继续通过，并补充列表选择、详情保存和未保存切换测试。

## 8. 非目标

- 不实现搜索、筛选、分页、批量启停或批量删除；
- 不实现拖拽排序（保留后续增强空间）；
- 不增加场景试运行、预览或聊天入口；
- 不改造场景预设后端数据模型和 API。
