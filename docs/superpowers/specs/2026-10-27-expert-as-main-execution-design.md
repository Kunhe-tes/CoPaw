# 显式选择专家的主执行模式

状态：设计已确认、功能已实施并完成本地验证（2026-10-27）；实际验收证据与环境限制见本次功能完成报告和测试报告。

## 用户已明确的需求

- 系统配置界面增加一个开关。
- 开启后，用户在会话中指定的专家担任 Main Agent，完成任务并直接回复。
- 关闭后保持当前行为，指定专家作为 SubAgent 执行。

## 已核实的现状

- 现有输入框专家控件按消息单选，提交后清空；请求携带 `selected_expert_id`。
- 当前显式专家执行由服务端强制启动所选专家并等待终态，随后由 Main Agent 汇总。
- 专家选择与 Plan 互斥；Goal 模式不接受该选择。
- 现有 Source 开关“允许自主选择我的专家”控制 Main Agent 的专家发现，不决定显式所选专家的执行身份。

证据：`console/src/pages/Chat/index.tsx`、`src/swe/app/runner/runner.py`、`src/swe/agents/tool_guard_mixin.py`、`docs/adr/0041-subagent-intent-and-configurable-expert-discovery.md`。GitNexus 绑定 `/Users/shixiangyi/code/Swe` 的 CoPaw 索引；首次检查为 2026-10-27 01:50 UTC。后续核查提示落后一个提交，已重建图索引，FTS 构建降级；涉及语义均另行核对源码。

## 第一轮已确认决策

1. 开关沿用 Source 级配置与现有管理员权限。
2. 只认现有专家选择器的结构化选择；正文提及专家名称不建立绑定。
3. 专家持续接管当前会话；后续消息未重新选择专家时仍由已绑定专家处理。
4. 保留专家声明的能力边界，不能因担任 Main Agent 而取得当前 Agent Profile 全量能力。社区专家的冻结私有依赖边界继续保留。
5. 本次仅覆盖普通聊天；不增加 Plan / Goal 中的专家执行能力。

上述决策由用户在第一轮逐项确认。开关默认关闭，已在第三轮确认。

## 现状与目标的差异

当前输入框提交后清空专家的行为只适用于既有 SubAgent 模式。新模式需要区分“显式选择动作”与“会话专家绑定”：后续请求即使没有重新选择，也不能误回退默认 Main Agent。绑定仍属于当前 Chat，不是把专家变成新的 Agent Profile。

现有专家 worker 每次使用 fresh context 且禁用长期记忆。新模式允许当前 Chat 上下文，但保留不使用 Profile 长期记忆的边界；执行预算按第二轮决策收窄。

## 第二轮已确认决策

6. 选择器持续显示当前绑定专家；选择另一专家切换，选择“默认 Agent”解除绑定。立即保存、下一条消息生效，已在第三轮确认。
7. 会话绑定持久化，刷新、重新进入和服务重启后恢复；恢复仍须满足 Source 和当前专家的有效性规则，具体处理见第三、四轮。
8. 专家可读取接管前及切换前的当前 Chat 已有上下文，沿用普通聊天的历史压缩与恢复机制。
9. 专家主执行不读取或写入所属 Profile 的长期记忆。
10. 专家配置的可用模型优先，否则使用当前聊天模型。
11. 专家主执行不能继续委派 SubAgent；包括不得经绑定 Skill 或 MCP 获得绕过该限制的委派能力。
12. 保留专家配置的执行上限，同时受 Main Agent 全局上限约束，逐项取更严格者。

上述七项已由用户逐项确认。专家身份、上下文、能力、模型与预算分开定义，不能因为主执行身份扩大依赖或权限。

## 第三轮已确认决策

13. Source 开关默认关闭。
14. 选择、切换或解除绑定后立即保存，从下一条消息生效；已开始的消息不在执行中更换执行身份。保存失败时不能呈现为已保存的新绑定。
15. 切入 Plan / Goal 时解除绑定，并向用户明确提示。
16. Source 关闭新模式后，既有绑定在下次进入会话或发送消息时失效。重新开启与失效消息处理见第四轮。

以上四项由用户逐项确认；不将开关关闭解释为立即中断正在执行的消息。

## 第四轮已确认决策

16a. 开关重新开启后，不自动恢复已失效的旧绑定；用户需要重新选择专家。
16b. 发送时才发现开关关闭，解除绑定并提示模式已关闭，保留消息供用户重新发送；本次不自动交给默认 Agent，也不转成专家 SubAgent 执行。
17. 绑定专家被禁用、删除、撤回或校验失败时，标记专家不可用并阻止本次执行，不自动换成其他专家或默认 Agent。
18. 下一条消息使用专家最新有效配置，正在执行的消息保持启动时的配置快照。社区专家仍只使用其当前本地已接收版本的冻结私有依赖；不因开始一条消息就从社区自更新。
19. 执行失败、达到上限或用户停止后，保留专家绑定并显示本轮终止原因。
20. 主对话直接流式输出，显示本轮实际专家身份，使用聊天停止按钮；本次主执行不创建 SubAgent 监控记录，也不经过默认 Main Agent 再总结。
21. 专家指令替代原 Profile 的角色指令；平台运行规则、安全约束和 Source 级公共规则继续适用。
22. 执行预算按每条消息独立计算，不跨消息累计；每轮仍取专家配置与 Main Agent 全局上限中更严格者。

以上由用户逐项确认。专家配置版本与执行身份在消息开始时确定，后续绑定变更不能改写已开始消息的身份或输出归属。

## 第五轮已确认决策

23. 专家主执行沿用主聊天的交互审批：需要审批时向用户展示入口，获准后才执行；专家的工具范围、平台安全边界和租户隔离继续适用。后台 SubAgent 的自动拒绝新审批规则不套用到本模式。
24. 同一 Chat 多页面中，旧页面提交时若绑定已被另一页面修改，阻止本次发送、同步最新绑定并提示身份变化，保留文本及附件引用供重发；不能让旧页面选择覆盖服务端最新绑定。
25. 新建会话或显式重置会话（包括 `/new`）清除绑定，回到默认 Agent。普通刷新、重进或服务重启仍恢复有效的原绑定。
26. 同一个专家身份从不可用恢复为有效后，保留的绑定可在下一条消息重新执行，发送前重新校验；删除后新建的同名专家不能接替原身份。该恢复不适用于已因 Source 开关、切换模式、重置或用户操作而解除的绑定。

以上四项由用户逐项确认。所有产品决策分支已收束，整体设计已获确认，后续实施与验证结果见交付报告。

## 已确认行为矩阵

| 条件或操作 | 必须出现的行为 |
| --- | --- |
| 开关缺省或关闭，无旧绑定 | 沿用现有专家单消息 SubAgent 路径 |
| 开关开启，未选择或绑定专家 | 普通聊天沿用默认 Agent |
| 开关开启，显式选择专家 A | 立即保存绑定；下一条由 A 主执行 |
| 后续消息没有新选择 | 继续由已绑定 A 处理 |
| 刷新、重进或重启 | 恢复仍有效的会话绑定 |
| 切换到 B 或默认 Agent | 立即保存变更，下一条生效；当前消息执行快照不变 |
| 切入 Plan / Goal | 解除绑定并明确提示；该模式不由专家接管 |
| 开关关闭后重进 | 既有绑定失效 |
| 发送时才发现开关关闭 | 解除绑定、提示、保留待发消息，不启动 Agent |
| 开关重新开启 | 不自动恢复已失效旧绑定 |
| 专家禁用、删除、撤回或定义无效 | 显示不可用，阻止本次执行，不自动替换身份 |
| 专家定义或本地收到的版本更新 | 下一条使用最新有效配置，在途使用原快照 |
| 主执行成功 | 专家流式回复，显示其身份，无二次总结、无新 SubAgent 记录 |
| 执行失败、超限或停止 | 显示本轮原因，保留绑定 |
| 切换专家或从默认 Agent 接管 | 可用当前 Chat 已有上下文，不加载 Profile 长期记忆 |
| 专家有可用指定模型 | 优先该模型，否则用当前聊天模型 |
| 专家或其 Skill 请求委派 | 不赋予继续委派 SubAgent 的能力 |
| 新消息开始 | 独立执行预算，逐维取专家和 Main Agent 全局更严格上限 |
| 专家主执行触发人工审批 | 沿用主聊天审批，获准后执行，不扩大专家工具范围 |
| 页面显示的绑定已落后于服务端 | 阻止发送、同步绑定并提示，保留文本和附件供重发 |
| 新建会话或显式重置（含 `/new`） | 清除绑定，回到默认 Agent |
| 同一专家身份恢复有效 | 保留的不可用绑定重新校验，下一条可执行 |
| 删除后新建同名专家 | 不自动替换旧身份，须显式选择新专家 |

## 实现时必须验证的既有边界

- 绑定只引用当前用户、Source、Chat 和所属 Agent Profile 下可用的专家，不能凭客户端参数跨租户或跨 Profile 访问。
- 社区版本更新后的私有依赖视图必须与该条消息采用的专家版本一致，不能复用同 Chat 旧缓存而混合新指令与旧依赖。已核查 `src/swe/app/subagents/session_dependencies.py:34-70,262-314` 当前按 Chat / definition_id / item_id 复用首次视图，不校验版本或内容指纹；新主执行模式必须按消息选定版本解析完整私有依赖快照。既有关闭开关的 SubAgent 路径保持原语义。
- 每次执行已有从依赖视图复制独立快照的机制，见 `session_dependencies.py:179-218`；新版本解析不能删除、改写正在使用的旧快照。
- 平台权限、审批规则、租户上下文、工具防护继续生效。已核查 `src/swe/agents/tool_guard_mixin.py:1673-1702,1987-1998`：SubAgent 遇到新的人工审批直接拒绝；Main Agent 在 `:2279-2328,2746-2776` 创建 pending 并输出审批入口。Q23 已确认专家主执行使用 Main Agent 交互审批链路。
- 启动执行前发现绑定失效属于未执行，客户端须保留原始文本及附件引用供重发；不能伪造已成功答复。
- 实施在独立 `feat/expert-as-main` worktree 完成；功能、测试及浏览器证据分别记入交付报告，设计确认不等同于生产环境已验收。
