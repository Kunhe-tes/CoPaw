# Tracing 有界重试与最终确认生命周期

## 目标与约束

Tracing 使用现有 MySQL，不新增 SQLite、文件日志或自动补偿服务。允许失败 span 在首次写入和两次重试后丢弃，但不得把缺失 span 或缺失聚合数据的 trace 标记完成。数据库故障期间，失败历史与待完成快照都必须有上限。

## 根因与链路

1. `emit_span` / `update_span` 等待 writer 接收成功后累计 input/output tokens、首个 model、tools、skills。这些聚合在最终更新前通常只有内存中的版本，数据库初始行仍可能全部为空。
2. writer 批量落库并确认具体 span 版本。永久数据错误会让整批失败；无限重试会占满队列，阻塞后续事件。当前每项最多尝试三次，耗尽后释放 payload，并将所属生命周期标记不可确认。
3. `end_trace` 先完成 skill detector，再确认 span，最后通过一次 MySQL UPDATE 写入聚合和终态。只有最后一步成功才算完成。
4. `flush` 超时不等于 span 丢失；数据库可能随后恢复。最终 UPDATE 失败或取消也不等于聚合已持久化，取消甚至可能发生在数据库已执行但确认未返回时。这些情况需要保留绝对值快照，使重试幂等。
5. 仅保留失败 ID 会泄漏内存；无条件清理活动 trace 则会丢失聚合，重试读取初始数据库行会产生错误完成记录。两种状态不能混为一谈。

## 状态与处理

| 状态/事件 | 聚合状态 | 是否可完成 |
| --- | --- | --- |
| 请求执行中 | `_active_traces` 累计 | 尚不可完成 |
| 开始最终确认 | 同 trace 禁止并发结束；skill detector 结束后封闭 span 接收 | 等待最终 span 版本确认 |
| flush 超时 / 最终 UPDATE 失败 / 取消 | 保存完整 Trace 快照，移出活动请求，清理当前任务上下文 | 可显式重试 |
| 使用快照重试 | 移回活动状态，防止重试时被淘汰；不读取旧数据库聚合 | flush 和 UPDATE 均成功后完成 |
| 确认后 UPDATE 成功 | 删除快照、预算、活动记录、接收封闭标志 | 已确认 |
| span 重试耗尽 / detector 最终清理丢失 | 删除大快照，保留有界失败证据 | 后续 flush 报错 |
| 快照超预算或淘汰 | 删除快照前标记不可确认 | 禁止回退旧数据库行完成 |
| 本地状态缺失、MySQL 行仍 running | 聚合来源不完整 | 拒绝完成，包括进程重启后的情况 |
| 本地状态缺失、MySQL 已是终态 | 数据已完成持久化 | 重复结束直接返回，不覆盖数据 |

同一 trace 在最终确认过程中不接收新 span；包括此前等待队列容量的提交，也会在获得容量后重新检查。失败后解除封闭，后续接受的事件继续更新待完成快照并重新计算预算。调用方应在事件生产结束后调用 `end_trace`。

默认重试保留首次最终确认的 status、error、end_time；显式传入 status 时允许更新最终意图。取消或异常向调用方原样传播。runner 的 `_end_trace_if_needed` 继续捕获普通 tracing 异常并记录日志；不新增自动重试任务。

## 内存预算与容量不足

- 待完成快照数量不超过 `max_queue_spans`，估算字节总量不超过 `max_queue_bytes`。预算使用固定开销加序列化长度的四倍估算，非精确 RSS 指标；该预算与 span 队列预算分别计算。
- 快照是深拷贝，不保留 TraceContext、skill detector、请求或任务对象。重试时从快照预算移到正在执行的活动状态。
- 先淘汰最早保留的快照，更新同一快照时重新计费；单个快照超预算则直接标记不可确认。
- 不保存历史失败 ID 黑名单。writer 注册表只保留当前生命周期状态，数量不超过 `max_queue_spans`；span 队列项、flush 等待者共享状态对象引用。永久失败时标记原状态后移出注册表；原等待者仍能看到失败，迟到旧批次不会污染新状态。
- 创建 trace 前预留注册名额；注册表满时先淘汰待重试快照，仍满则快速拒绝 tracing 创建，不写入新的 running 行。名额释放后自动恢复，无需重启。正常完成和创建失败都释放名额。
- 未知 trace 的 submit/单 trace flush 均不能自动建立新状态。完成资格来自本地已注册生命周期及完整聚合，不能由“当前没有失败记录”推导。
- `attach_existing` 的外部生产者共享本地状态，最后一个附加上下文释放后移出外部注册；队列项仍持有状态。外部注册本身不赋予本地聚合或跨 Pod 完成权限。已有本地 owner 的生命周期不因附加上下文结束而回收。
- `flush(None)` 在调用时捕获当前注册状态和队列项版本。目标在等待中失败则本次调用失败；已经回收的历史失败不影响后来的全局 flush。成功终结的状态仍能被之前的全局等待者判为成功。关闭 writer 时输出累计 span 丢失数，队列为空不等于历史无丢失。

## 恢复与边界

快照仍在、无永久失败时，数据库恢复后再次调用 `end_trace` 可写入原聚合。快照已淘汰或 span 已丢失时，禁止自动完成。数据库恢复后新 trace 有独立的状态，可正常写入和完成，不需重启或重置历史标志；历史 running trace 不可通过旧记录伪造完成。修复前版本的 `_failure_index_overflow` 需要通过升级部署移除，不能只在旧进程内清空失败集合。

活动请求仍按正常请求生命周期管理；本变更控制的是故障后滞留的状态，不为尚未结束的业务请求施加并发上限。不提供跨进程快照恢复或自动重试 finalization。

## 验证

回归覆盖最终 flush 超时、UPDATE 异常、两个阶段真实任务取消、所有聚合字段恢复、默认重试保留终态意图、重复结束幂等、并发结束、封闭后拒绝新事件、快照数量/字节预算、淘汰后拒绝旧数据库回退、持续失败超过旧上限后自动恢复、新旧 flush 隔离、未知 trace 迟到提交、注册容量拒绝与释放、附加上下文释放及旧批次状态隔离。
