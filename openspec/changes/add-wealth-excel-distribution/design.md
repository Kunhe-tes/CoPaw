## Context

创建页通过 TargetPicker 收集分发目标。Console 向外部 `/zt/wealth/plans` 提交 `targets`，每项包含 `sapId`、`name`、`bbkId` 和 `bbkOrgId`。

## Scope

在现有分发步骤增加可独立授权的 Excel 名单入口。实现范围为 Console 及外部服务契约对接。工作台可见规则和下游任务执行沿用现有流程。

## Decisions

- 使用真实登录 SAP 用户 ID 判断白名单权限，默认关闭。仅在已有分发目标选择权限的角色中开放。运维模式切换后的分行和角色不授予导入能力。外部服务必须依据真实登录身份落实授权，前端负责入口和提交路径控制。
- 对符合资格的用户，在分发步骤顶部展示互斥单选。新建默认 Excel，切换时保留当前表单中的两份选择，发布确认只读取当前方式。白名单用户编辑时默认在 Excel 名单管理中回显已保存的收件人，可直接移除人员。上传增量表只查询当前名单中缺少的 ID，确认后追加。上传完整表经过确认后整体替换。取消导入保留当前名单，预览期间先确认或取消再按 Excel 方式保存。新建、关闭和上下文切换时清理导入状态。
- Excel 区域提供模板下载、上传和更换文件。核对区默认展示全部人员卡片，每页 24 人。每张卡片展示姓名、SAP 用户 ID、分行和机构。支持全文搜索、分行下拉筛选和逐人移除，发布确认使用剩余名单。更换文件整体替换名单。异常仍按行号提示。
- 固定模板使用一张名单表，A 列为文本格式的客户经理ID，B 列客户经理姓名选填。人员查询与去重以 ID 为准，兼容原单列 SAP 用户 ID 模板。使用原生 ZIP 条目解压和 XML 解析，支持共享字符串及内联文本。限制文件大小为 5 MB、单个解压 XML 为 4 MB，保留前导零。人数由文件大小自然约束。文件留在浏览器。
- 假设外部已有智拓人员查询能力，复用统一请求与鉴权，在 API 模块声明同源路径，与现有 `/agent/workspace` 接口一致。按 ID 匹配查询结果，将人员信息映射为现有目标结构，机构名称用于预览。一次提交全部去重后的 SAP 用户 ID，查询失败可重试，过期请求结果不能覆盖当前文件或表单。
- 将当前确认的收件人交给现有发布流程。修改确认显示相对原名单的新增人数、移除人数和最终人数。规划与场景仍以发起上下文为准。Excel 目标使用各自的分行和机构编码。

## Risks and verification

- 前端白名单配置为 `wealthExcelDistributionUsers`。人员接口暂按 `POST /agent/workspace/users/by-sap-ids`、`{ sapIds: string[] }`、`code="200"` 与人员数组设计，前端一次发送完整查询名单。路径和字段语义仍需联调确认。外部发布接口的跨分行支持和授权校验是启用白名单的前置条件。
- 实际 360 浏览器可能与 Chromium 源码基线有差异。通过能力检测提示解析不可用，并保留按机构选人入口。使用真实 Chromium 108 或对应 360 内核、当前浏览器及适用的 `hideMenu=true` 场景验收。
- 白名单启用前先验证非白名单的普通和运维流程，以及跨分行收件人确实进入下发范围。
