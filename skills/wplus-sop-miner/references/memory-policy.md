# W+ 记忆策略

## 读取顺序

提出第一个澄清问题前，依次尝试读取：

1. `memory/common-wplus-knowledge.jsonl`
2. `memory/users/{user_scope}/wplus-usage-preferences.jsonl`
3. `memory/cases/sop-cases.jsonl`

文件不存在表示当前没有对应记忆，不要仅因为文件缺失就创建文件。

只允许使用调用方提供的匿名化 `user_scope`。如果没有提供，则跳过个性化记忆。不得询问或使用员工号、客户标识、电子邮箱或真实姓名作为范围键。

## 允许保存的记忆

- 客观、可复用、已验证的页面或平台事实。
- 不含敏感信息的个人工作偏好和判断习惯。
- 无法追溯到具体客户或交易的完全脱敏 SOP 模式。

## 禁止保存的记忆

- 客户姓名、标识、账号或卡号、余额、交易明细、持仓、自由文本备注、电话号码或地址。
- 凭证、Cookie、令牌、内部用户绝对路径、加密卡号或原始接口响应。
- 被当成事实保存的未确认模型推断。
- 只在单一客户案例中观察到的阈值或规则；除非用户明确确认这是其个人习惯，且内容不含客户数据。

## 候选与确认流程

最终 SOP 输出后，展示每个记忆候选的类型、拟写内容和准确对话证据，并分别询问用户哪些可以写入。一个候选获批不代表其他候选也获批。

使用 `scripts/memory_store.py --approved` 写入获批候选。脚本会执行隐私检查，并避免重复写入相同类型和内容。如果候选被拒绝，应修改或放弃该候选，不得绕过检查。
